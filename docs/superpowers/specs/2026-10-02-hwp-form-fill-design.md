# 양식으로 새 문서 (한글 양식 채우기) 설계

- 날짜: 2026-10-02
- 상태: 설계 승인, 구현 전
- 브랜치: `feat/hwp-form-fill` (기반: `feat/ai-thinking-stream` — 그 아래 `feat/hwp-ai-engine-surface`, 둘 다 main에 병합 전)
- 범위: `apps/hwp`(열기 방식, AI 도구, 편집 체인 검증, 패널 안내), `apps/shell`(홈 카드·메뉴·파일 선택), 시스템 프롬프트.
- 선행 확인: 2026-10-02 실제 양식 확인 (서울시 정보소통광장 hwpx 4종, 프리폼 hwp 13종 중 6종을 앱 AI 패널로 채움). 결과는 §1.

## 1. 배경 — 실제 양식으로 확인한 사실

| 양식                                    | 형식    | 결과                                                                                         |
| --------------------------------------- | ------- | -------------------------------------------------------------------------------------------- |
| 서울시 결재문서본문 (누름틀 39개, 표 3) | HWPX    | 누름틀 9개 채움. 본문 문구 교체는 엔진 검증 거부로 되돌려짐                                  |
| 서울시 약식보고서 (표 4)                | HWPX    | 요청한 8줄 정확히 반영, 서식 유지. 안내용 표 2개는 지우지 못함                               |
| 서울시 보고서(계획서) 3쪽 (표 7)        | HWPX    | DeepSeek: `find`·`read_table` 30회 이상 후 빈 응답("No reply."). Codex: 11줄 작성 후 턴 한도 |
| 품의서 · 자동차 매매계약서 · 공문 7쪽   | HWP 3.0 | 표 칸·본문 채움, 서식 유지. 저장하면 HWP5                                                    |

1. **원본 덮어쓰기:** 양식을 열어 채우고 ⌘S를 누르면 양식 원본이 바뀐다.
2. **엔진 검증 거부:** rhwp `edit … --verify`는 원본과 결과를 비교하지 않는다. **저장본을 다시 읽은 IR과 메모리 안의 IR**을 비교한다(CLI 문구: "저장본 재파싱 IR 차이").
   - 한컴이 만든 양식은 저장된 줄 배치 캐시(`vpos`·`ls`·표 셀 `line_segs`)가 엔진 계산과 달라, 단어 하나 치환이나 내용 변화가 없는 치환도 exit 3을 낸다.
   - `ir-diff 원본 결과`의 차이 22건 중 19건이 이 캐시이고, 나머지는 의도한 `text` 변화였다.
   - 같은 결과 파일을 다시 저장하면 `ir-diff`는 0건이다. 결과 파일 자체는 안정적이다.
   - 엔진이 만든 문서(스캐폴드)와 약식보고서는 같은 치환이 통과한다(`identical: true`).
3. **탐색 비용:** 표가 많은 양식에서 모델이 `find`와 `read_table`을 한 칸씩 부르다 차례 한도(8)에 걸린다.
4. **삭제 불가:** 엔진에 `delete-table`이 있으나 AI 도구에 없다. 한 행짜리 표의 행 삭제는 거부된다.
5. **빈 응답:** 모델이 글도 도구 호출도 없이 차례를 끝내면(DeepSeek 생각 모드에서 생각만 하고 끝남) 패널은 "No reply."만 보인다. 턴 한도에 걸리면 "Turn limit reached."만 보인다.
6. **형식:** 프리폼 서식은 모두 HWP 3.0이었다. rhwp가 열기·편집·HWPX/HWP5 변환을 모두 처리한다.
7. **이용 조건:**
   - 서울시 서식은 공공누리 제4유형(출처 표시·상업적 이용 금지·**변경 금지**)이다.
   - 프리폼은 이용약관 제6조에 따라 무단 복제·배포를 금지한다.
   - **두 곳의 양식은 앱·저장소·테스트 픽스처에 넣지 않는다.**

## 2. 목표와 성공 기준

**목표:** 사용자가 가진 양식(hwp/hwpx)으로 "새 문서"를 만들고, AI가 칸과 본문을 채운다. 원본은 바뀌지 않는다.

**성공 기준** (§1의 확인을 같은 양식·같은 요청으로 다시 돌려 판정한다. 양식 파일은 사용자 PC의 `D:\tmp\forms`에만 둔다)

1. 양식 복사본으로 연 탭은 ⌘S를 누르면 "다른 이름으로 저장"이 뜨고, 원본 파일은 바이트 단위로 그대로다.
2. 서울시 결재문서본문에서 본문 문구 교체가 적용된다.
3. 서울시 약식보고서에서 안내용 표가 지워진다.
4. 서울시 보고서(계획서) 3쪽에서 Codex와 DeepSeek 모두 편집에 도달하고, 끝날 때 "No reply." 대신 한 일과 남은 일을 알린다.
5. HWP 3.0 양식 3종은 지금과 같이 채워진다 (퇴행 없음).

**목표가 아닌 것**

- "내 양식" 폴더와 양식 목록 (다음 단계)
- 웹에서 받은 양식의 내장, 양식 자동 검색
- 화면 편집(스튜디오 명령)으로 하는 대체 적용 경로

## 3. 결정 사항 (사용자 확인)

| 항목      | 결정                                                                                               |
| --------- | -------------------------------------------------------------------------------------------------- |
| 시작 방식 | 홈 "양식으로 새 문서" 카드 + 메뉴 → 파일 선택 → 복사본을 이름 없는 새 탭으로 (내 양식 폴더는 나중) |
| 검증 완화 | 레이아웃 캐시 차이만 있으면 통과, 구조가 달라지면 지금처럼 거부                                    |
| 양식 지도 | 한 번 호출로 입력 칸·표 칸·본문 문단을 돌려주는 도구                                               |
| 삭제      | 표 삭제 도구 추가                                                                                  |
| 차례 한도 | 8 → 20, 끊기거나 빈 응답이면 안내                                                                  |

## 4. 설계

### 4.1 양식 복사본 열기

1. **시작 지점**
   - 홈 새 문서 카드 줄에 `{ ext: 'hwp', title: t('newHwpFromForm'), sub: '양식 파일 (.hwp/.hwpx)' }` 카드를 추가한다.
   - 파일 메뉴에 "양식으로 새 한글 문서…"를 추가한다.
2. **파일 선택**
   - 메인(`apps/shell/src/main/index.ts`)이 `dialog.showOpenDialog`로 `.hwp`·`.hwpx` 하나를 고르게 한다.
   - 50 MB를 넘으면 열지 않고 알린다.
3. **새 열기 방식:** `HwpOpenIntent`에 `{ mode: 'form'; fileName: string; data: ArrayBuffer }`를 추가한다.
   - 메인이 파일을 읽어 바이트로 넘긴다.
   - **경로는 넘기지 않는다.** 탭은 원본 경로를 모르므로 원본을 저장 대상으로 삼을 수 없다.
   - 기존 `{ mode: 'open'; path }`(파일 열기)와 `{ mode: 'blank' }`(빈 문서)는 그대로다.
4. **렌더러(`App.tsx` 시작 처리)**
   - `form`이면 `editor.loadFile(bytes, fileName)`로 불러온다.
   - `filePathRef.current = null`로 두어 저장이 "다른 이름으로 저장"으로 가게 한다.
   - 탭 이름은 `${양식 이름} (새 문서)`로 하고, 상태 표시줄에 "양식에서 만든 새 문서 — 원본은 바뀌지 않습니다"를 한 번 보인다.
5. **다른 이름으로 저장**
   - 기본 이름은 `${양식 이름}_작성`과 원래 확장자다.
   - HWP 3.0에서 온 문서는 `.hwp`로 저장하고 내용은 HWP5다 (기존 `saveNow`의 확장자 규칙 그대로).
6. **실패**
   - 엔진·스튜디오가 열지 못하는 파일(암호 문서, 손상)이면 오류를 알리고 빈 탭을 남기지 않는다.
   - 파일 선택을 취소하면 아무 일도 하지 않는다.
7. **AI 대화 식별:** 이름 없는 문서와 같은 방식(`tempChatId`)을 쓴다. 저장하면 기존 rebind 경로로 파일에 묶인다.

### 4.2 양식 지도 도구 `form_map`

- **입력:** `{ page?: number }`. 쪽 수가 많은 양식은 쪽 단위로 나눠 받는다.
- **출력** (한 번 호출, 문서 내용은 기존 `⟦문서 내용:nonce⟧` 울타리로 감싼다)
  - `fields`: 누름틀 이름·안내·현재 값·좌표 (`fields` 쿼리)
  - `tables`: 표 번호, `rows×cols`, 칸마다 `{row, col, text, empty}` (`export_tables` 쿼리). 병합 칸은 기준 칸만 둔다.
  - `paragraphs`: 본문 문단마다 `{section, paragraph, text, empty, hasTable}` (새 `paragraphs` 쿼리, 아래)
  - `summary`: "누름틀 N개(빈 칸 k개), 표 T개(빈 칸 c개), 본문 문단 P개(빈 문단 e개)"
- **새 쿼리 `paragraphs`**
  - `rhwp dump <파일>` 텍스트에서 `--- 문단 S.P ---`와 그다음 `텍스트:` 줄을 읽어 만든다. `(빈 문단)`은 빈 글로 보고, 같은 문단 안 `[n] 표:` 줄이 있으면 `hasTable`로 표시한다.
  - rhwp 버전이 고정(0.8.6)이므로 형식은 실바이너리 계약 테스트로 고정한다.
- **상한:** 출력은 기존 읽기 도구 상한(24,000자)을 따른다. 넘으면 `truncated: true`와 "page를 지정해 다시 부르라"는 안내를 붙인다.
- **시스템 프롬프트:** "양식(누름틀이나 빈 칸이 있는 문서)을 채울 때는 `find`나 `read_table`을 칸마다 부르지 말고 먼저 `form_map`을 한 번 부른다. 누름틀은 `fill_fields`, 표 칸은 `edit_table`의 `set_cell`로 한 번에 묶어 채운다."

### 4.3 레이아웃 캐시 허용 검증

편집 체인(`apps/hwp/src/main/ai-edit-chain.ts`)의 마지막 단계는 지금처럼 `--verify`로 실행한다. exit 3(검증 실패)이면 바로 거부하지 않고 다음 순서로 판정한다.

1. 결과 파일이 다시 열리는지 본다 (`explain` exit 0). 열리지 않으면 거부한다.
2. `ir-diff 원본스냅샷 결과 --json`의 `categories`를 읽는다.
3. 각 범주를 분류한다.
   - **캐시(항상 허용):** `vpos`, `ls`, `lh`, `th`, `bl`, 그리고 `tbl cell[`로 시작하는 범주 (rhwp 0.8.6이 셀 문단의 `line_segs`와 셀 글 차이를 이 이름으로 낸다)
   - **내용(허용):** `text`
   - **구조:** 그 밖의 모든 범주 (`tbl rows`, `tbl size`, `tbl 셀 수`, `controls count`, `char_shapes count`, `구역 …` 등)
4. 구조 범주가 있으면, 이번 묶음의 편집 종류가 그 범주를 낼 수 있는 것일 때만 허용한다.

   | 편집 종류                                        | 허용되는 구조 범주                                                                                  |
   | ------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
   | 행·열 추가·삭제, 셀 병합·분할, 표 만들기         | `tbl rows`, `tbl cols`, `tbl size`, `tbl 셀 수`                                                     |
   | 문단 추가·삭제, 쪽·단 나눔                       | `controls count`, `char_shapes count`, `char_offsets len`, `tab_ext count`, `cc`, `ps_id`, `구역 …` |
   | 표 삭제                                          | 위 두 줄 모두                                                                                       |
   | 각주·책갈피·머리말                               | `controls count`, `cc`                                                                              |
   | 그 밖(치환, 문단 글 바꾸기, 셀 글, 누름틀, 서식) | 없음 — 구조 범주가 나오면 거부                                                                      |

5. **불변 조건:** 허용하더라도 원본과 결과의 `explain`을 비교해 다음 중 하나라도 어긋나면 거부한다.
   - 누름틀 이름 목록이 같다 (값은 달라도 된다)
   - 표 만들기·표 삭제가 없는 묶음이면 표 개수가 같다 (있으면 그 수만큼만 다르다)
   - 구역 수가 같다
6. **허용한 경우**
   - 편집 결과를 그대로 쓰고, 편집 보고에 `verify: 'layout-tolerant'`와 쪽 수 변화(`pagesBefore → pagesAfter`)를 적는다.
   - 모델에게 가는 요약에는 "레이아웃 계산값만 달라 통과" 한 줄을 넣는다.
7. **거부한 경우:** 지금과 같은 오류(`describeRhwpFailure`)에 "구조가 달라졌습니다: 범주 목록"을 덧붙인다. 범주 이름은 엔진이 만든 고정 문자열이고 문서 내용이 아니다.
8. **계약 테스트 픽스처**
   - 서울시 양식은 저장소에 넣지 못한다. 대신 스캐폴드 HWPX의 `section0.xml`에서 `lineseg`의 `vertpos`를 일부러 바꾼 **합성 픽스처**를 만든다.
   - 이 픽스처에서 치환이 `--verify` exit 3을 내고, 이 판정으로 통과하는지 실바이너리로 확인한다.
   - 픽스처를 만드는 스크립트를 테스트 폴더에 둔다.

### 4.4 표 삭제 도구

- `edit_table`의 연산에 `delete_table {table}`을 추가한다.
  - 엔진 `edit delete-table --section/--para/--ctrl`로 옮긴다.
  - 표 번호→좌표 변환은 기존 표 연산과 같다 (`export_tables`의 `section/paragraph/control`).
- `delete_row`가 그 표의 마지막 행이면 엔진에 보내기 전에 "한 행짜리 표는 `delete_table`로 지운다"는 인자 오류로 돌려준다.
- `delete_paragraph`가 구역의 마지막 문단이면 "문단 글을 비운다"(`set_paragraph_text`의 빈 글)로 바꿔 보낸다. 엔진은 마지막 문단 삭제를 거부한다.

### 4.5 차례 한도와 끊김 안내

- 한글 패널 `AgentLoop`의 `maxTurns`를 8 → 20으로 올린다 (엑셀은 24).
- **턴 한도에 걸림:** 지금 마지막 줄 "Turn limit reached."를 아래 안내로 바꾼다.
  - "작업이 길어져 여기서 멈췄습니다. 지금까지 적용한 편집 N건. '계속'이라고 입력하면 이어서 진행합니다."
  - N은 이번 실행에서 `mutated: true`였던 도구 수다.
- **빈 응답:** 마지막 차례에 글도 도구도 없으면 "No reply." 대신 안내를 보인다.
  - 편집이 있었으면 "모델이 설명 없이 끝냈습니다. 적용한 편집 N건은 ⌘Z 또는 'AI 편집 되돌리기'로 되돌릴 수 있습니다."
  - 편집이 없었으면 "모델이 답 없이 끝냈습니다. 다시 요청하거나 다른 모델을 골라 보세요."
- 문구는 한국어·영어 두 벌이다 (패널의 기존 `lang` 규칙).

## 5. 오류 처리

- 파일 선택 취소, 50 MB 초과, 열 수 없는 형식: 탭을 만들지 않고 알린다.
- 판정에 쓰는 `ir-diff`나 `explain`이 실패하면 허용하지 않는다 (안전한 쪽 = 지금 동작).
- `form_map`의 일부 쿼리가 실패하면, 실패한 부분을 `unavailable: ['tables']`처럼 표시하고 나머지는 돌려준다.

## 6. 테스트와 수용

### 6.1 자동 테스트 (먼저 실패하는 테스트)

- **shell:** 양식 선택 → `form` 열기 방식(경로 없음, 바이트·이름 전달), 취소·크기 초과
- **hwp 렌더러:** `form`으로 연 탭은 `filePathRef`가 없고 저장 시 `saveAs`를 부름, 기본 저장 이름
- **hwp 메인**
  - 판정 함수: 캐시만 → 허용, 구조 + 맞는 편집 종류 → 허용, 구조 + 안 맞는 편집 종류 → 거부
  - 판정 함수: 누름틀 이름이나 표 개수가 바뀌면 거부, `ir-diff` 실패 → 거부
  - 합성 픽스처로 실바이너리 계약 테스트
- **`paragraphs` 쿼리:** `dump` 텍스트 파싱 (빈 문단, 표 표시), 실바이너리 계약 테스트
- **`form_map`:** 세 부분 조립, 울타리, 상한·쪽 지정, 일부 실패
- **표 삭제:** `delete_table` 연산 변환, 마지막 행 `delete_row` 거부, 마지막 문단 삭제 → 글 비우기
- **패널:** `maxTurns` 20, 턴 한도·빈 응답 안내 (편집 있음/없음)

### 6.2 실제 확인

§1의 6개 양식에 같은 요청을 다시 돌린다. 양식은 `D:\tmp\forms`에 있고 드라이버는 gitignore 대상인 `scripts/drivers/driver.hwp-form-fill.mjs`다.

- 서울시 3종은 Codex와 DeepSeek 둘 다 돌린다.
- 이번 결과를 §1 표 옆에 적어 §2의 성공 기준 1~5를 판정한다.
- 홈 "양식으로 새 문서"로 연 탭에서 ⌘S가 "다른 이름으로 저장"이 되는지, 원본의 바이트가 그대로인지(SHA-256 비교) 확인한다.
